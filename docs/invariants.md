# 건드리면 안 되는 것

- ETF 페이지 진입·수동 재확인마다 게시 자료를 재검증하고 인증된 no-store API로 보유 종목의 원본을 조회한다. 동시 조회는 2개, 이전 진입의 늦은 응답은 무시한다. 실패·이전 기준일·기준일 없는 일부 자료가 마지막 정상 비중을 덮어쓰지 않는다. 조회 상태와 구성 기준일을 별도로 표시한다. 화면 조회 이력은 세션에만, 정기 이력은 배치로 저장한다. 함수에서는 긴 KRX·브라우저 재시도를 실행하지 않는다.

- 2026-09-10 화면 정리: 재무상태표 메뉴·화면은 제거하고 이전 balance2 링크는 홈으로 보낸다. 기존 기타 자산·부채 데이터와 기록 배치는 목표·합계 계산에 쓰이므로 삭제하지 않는다. 홈의 중복 순자산 요약·할 일·추이는 제거하고 자산 배분·섹터·기여도 옆에 수익률/손실률 TOP5를 위아래로 쌓고 전체 높이를 맞춘다. 세금 요약 6개도 한 행이며 작은 화면에서는 읽을 수 있도록 나눈다. 배당·세금·증여 근거는 각 페이지 최하단에 유지한다.
- 국내 ETF의 FunETF 자료는 공개 상품 목록의 식별자와 전체 PDF 구성종목 응답을 사용한다. 페이지에 발표된 구성 기준일·응답 종목 수·상품 식별자를 대조하고 원래 비중을 유지한다. 월간 상위 종목만 있는 자료와 혼동하지 않는다. 실패하면 기존 조회 경로로 넘어간다. 미국 티커 KR·KRC를 한국 채권/현금 ISIN으로 오인해 제외하지 않는다.
- ETF 정기 수집은 미국 장 마감 뒤 평일 1회 실행한다. 구성·기준일·출처·품질·이력이 같고 시각 메타데이터만 달라졌으면 JSON을 다시 쓰거나 커밋하지 않는다. 데이터 JSON만 바뀐 커밋은 Vercel 함수를 재배포하지 않으며, 화면은 GitHub의 최신 원본을 먼저 읽고 배포 사본으로 폴백한다. 코드나 설정이 함께 바뀌면 반드시 정상 배포한다.

- ETF 탐색의 소유주 필터는 재클릭하면 전체로, 종목은 재클릭하면 선택 해제로 돌아간다. 소유주 비중 카드는 카드 전체가 하나의 네이티브 펼침·접힘 영역이다. 보유·확인·점검 수치는 보유 ETF 선택 위젯 내부에 표시한다.
- QLD 공식 표의 실제 기준일과 직접 보유 주식 비중을 사용한다. 스왑·MMF·빈 티커는 제외하고 잘린 표나 잘못된 비중은 전체 자료로 인정하지 않는다. 목표 레버리지를 주식 구성비로 대체하지 않는다. 비중 분석은 Plotly 로딩 실패 시에도 목록을 표시하며 같은 소유주·자산군·정규화 티커의 계좌만 합친다.

## 메뉴 통합·가상 투자 계산·적립식 규칙

- 상위 메뉴는 홈, 자산 관리, 투자 분석, 배당, 투자 계획, 현금 흐름, 세금·증여 7개다. `navigation.js`가 기존 화면 ID를 내부 메뉴에 연결한다. 예전 `snap`·`balance2` 링크는 홈으로 해석하며 뒤로·앞으로 이동, 메뉴 강조, 관련 탭 간 소유주 범위를 유지한다. 홈에는 소유주 필터와 검색이 적용되는 보유 종목 표를 유지하며 편집은 자산 관리에서 한다.
- 투자 계획은 목표(`plan2`), 리밸런싱(`rebal2`), 적립식 매수(`dca2`), 시뮬레이터(`sim2`)로 나눈다. 스크립트 순서는 세금 규칙 → 원장 → finance → navigation → simulator → dca-editor → cobalt → 3D다. `workspace-ui.css`는 기본 CSS 다음에 로드한다.
- 시뮬레이터는 저장되지 않는 가정이다. 추가 투자금은 외부 유입 자금이며 기존 현금을 빼지 않는다. 가격·환율 고정, 수익률 0%, 매도·세금·수수료·배당·매수 단위 제외를 화면에 명시한다. 비중 합계가 100%가 아니면 결과를 숨기며 원 단위 배분 합계는 입력 예산과 같아야 한다. 모바일에서도 가상 입력은 허용하지만 실제 원장은 조회 전용을 유지한다.
- 시뮬레이터와 새 적립식 규칙의 숫자 입력은 `data-no-comma="1"`로 전역 천단위 표시 변환에서 제외한다. 결과만 갱신해 입력 포커스를 유지한다. 적립식 규칙 저장은 원장·재무계획 로드 완료 후 기존 CAS 저장을 거치고, 편집한 계좌 객체가 바뀌었다면 저장을 거절한다. 가격·평단가·수량·취득가 미상 표시는 바꾸지 않으며 실패 시 기존 규칙을 복구하고 입력 초안은 남긴다.

이 저장소를 고치기 전에 한 번 읽는 문서입니다.
여기 적힌 것들은 **한 번씩 실제로 사고가 났던 자리**이고, 대부분은 화면이 멈추는 게 아니라

## 1. 절대 하지 말 것 — 돈과 기록이 걸린 것

### 1-1. 세금·증여 숫자를 코드에 직접 쓰지 않는다

세율·공제액·기준금액은 **`tax-rules.js` 한 파일에만** 있습니다.
계산하는 쪽은 `assetTaxRuleValue` / `_taxRuleValue` 를 통해서만 읽습니다.

편해 보인다고 `0.154` 같은 숫자를 계산식에 직접 적으면, 법이 바뀔 때 어디를 고쳐야 하는지
아무도 모르게 됩니다. 화면에는 계속 옛날 세율로 계산된 금액이 나옵니다.

세금 값을 바꿀 때는 값·출처·가정·`verifiedAt`·`nextReviewAt`·버전을 **한꺼번에** 고치고
`docs/tax-rule-changelog.md` 에 기록을 남긴 뒤 `npm run check:tax-rules` 를 돌립니다.

### 1-2. 배당세 계산을 새로 만들지 않는다

배당 세후 금액을 구하는 엔진은 `script.js` 의 `allocateDividendTax` **하나뿐**입니다.
배당 이력·캘린더·계좌 진단·가계부 자동 등록이 전부 이 함수를 거칩니다.

새 화면을 만들면서 "여기서만 간단히" 세금을 계산하면 화면마다 다른 금액이 나옵니다.
특히 ISA 공제를 종목별 반복문 안에서 적용하면 **세금이 통째로 사라집니다** — 공제를
종목 수만큼 중복 적용하기 때문입니다. 반드시 보유 종목을 한꺼번에 넘겨야 합니다.

> ISA 계산은 연간 현금흐름 **참고치**입니다. 실제 ISA 세금은 계좌 만기·해지 때
> 가입 기간 전체 손익으로 정산되므로, 화면 표기에서 '연간 현금흐름 참고' 라벨을 떼면 안 됩니다.

### 1-3. 티커 상한(25 / 20)을 올려서 해결하지 않는다

서버는 요청 하나에 담긴 종목 수를 검사합니다. 시세·배당은 **25개**,
성과 비교 벤치마크는 **20개**가 상한입니다. 넘기면 서버가 그 요청을 **통째로 거부**합니다.

증상: 보유 종목이 늘어난 순간 **시세·배당·성과 라인이 한꺼번에 비고**,
데이터 상태가 영구히 '확인 필요'로 남습니다.

이건 보안상 입력 검증이라 **올려서 고치는 게 아니라** 나눠 보내서 고칩니다.
`_chunkTickers()` 로 잘라 보내고 결과를 합칩니다. 일부만 실패하면 성공분은 반영하되
**실패를 숨기지 않고** 보고해야 합니다.

### 1-4. 원장을 불러오지 못한 상태에서 저장하지 않는다

`window._kvLoadState` 가 `ready` 가 아니면 저장 함수들이 쓰기를 거부합니다.
이 방어를 빼면 **불러오기 실패 → 빈 화면 → 그 빈 상태를 서버에 저장** 순서로
실제 자산 기록이 지워집니다.

### 1-5. 날짜 키를 `toISOString()` 으로 만들지 않는다

`toISOString()` 은 세계 표준시(UTC)라 한국에서는 **오전 9시 이전에 어제 날짜**를 돌려줍니다.
반드시 `finance.js` 의 `finLocalDateKey()` 를 씁니다.
순자산 스냅샷 키, 현금 흐름 기간, "오늘 제외" 판정이 전부 하루씩 밀립니다.

### 1-6. 배당 자동 가계부 기록을 함부로 지우지 않는다

`autoAddDividendCashFlow` 는 앱이 만든 배당 기록을 지울 수 있습니다.
지워도 되는 근거는 **확실한 것 세 가지뿐**입니다 — 종목을 팔았거나, 사용자가 지웠거나,
**조회에 성공한** 일정에 그 달 지급이 없거나.

내장 DB 폴백(`_divSource === 'db'`)은 **조회가 실패했을 때도 나타납니다.**
이걸 삭제 근거로 삼으면 **네트워크가 한 번 끊긴 것만으로 실제 배당 기록이 사라집니다.**

### 1-7. 테스트를 끄거나 건너뛰어서 초록으로 만들지 않는다

이 저장소에는 **CI 에서 조용히 건너뛰던 테스트가 한동안 방치된 적**이 있습니다
(`test_benchmark_columns.py` — pandas 미설치 시 자기가 SKIP). 지금은 CI 환경에서
건너뛰면 실패하도록 바꿔 뒀습니다. 이 장치를 되돌리지 마세요.

## 2. 조용히 틀린 숫자를 보여주게 되는 것

### 2-1. 소유주 필터를 통과시키지 않은 계산

소유주 탭(본인/아내/자녀1/아버지)을 누르면 **그 화면의 모든 숫자**가 따라가야 합니다.
가구 전체 합계가 한 칸이라도 새어 나오면 사용자는 그걸 그 사람의 자산으로 읽습니다.

구조상 소유주별로 나눌 수 없는 숫자(예: 순자산 브리지 — 가구 단위 스냅샷만 존재)는
계산을 억지로 하지 말고 카드에 **"가구 전체"** 라고 표시합니다.

### 2-2. 데이터 신선도를 메모리 상태로 추론

"데이터 상태" 화면의 초록불은 **실제 조회 성공 기록(`finMarkFresh`)** 이 있을 때만 켜집니다.
`pfolioData.length >= 0` 같은 검사는 **항상 참**이라 영원히 꺼지지 않는 가짜 초록불이 됩니다.

세 가지 상태를 구분해야 합니다 — `ok`(조회 성공) / `warn`(조회 실패) / `pending`(아직 조회 안 함).
`pending` 은 오류가 아니므로 빨간색으로 칠하면 진짜 오류가 묻힙니다.

### 2-3. 배당 조회 완결성을 캐시 키 개수로 판정

`_divDataCache` 에는 **배당이 있는 종목만** 들어갑니다. 무배당 종목은 조회에 성공해도
행이 생기지 않습니다. 그래서 "캐시에 몇 개 있나"로 판정하면 **무배당 종목이 전부
'조회 실패'로 잡혀** 멀쩡한 화면에 경고가 뜹니다.

판정은 `window._divFetchCoverage` 의 verified 목록으로만 합니다.
판정할 근거가 아직 없으면 경고하지 말고 **'확인 중'** 으로 둡니다.

### 2-4. 배당 지급월 기본값을 두 군데서 다르게

API 가 지급월을 안 알려준 종목의 기본값은 `cbDefaultDivMonths` **하나만** 씁니다.

과거에 월별 막대만 "주기대로(연 1회면 12월)" 고치고 '다가오는 배당'은 분기 가정을
그대로 둔 적이 있습니다. 결과는 **같은 화면 안에서 두 위젯이 서로 다른 일정**을 그리는 것이었습니다.

### 2-5. 순자산 스냅샷을 구조 확인 없이 분류

과거 기록은 세 가지 모양이 섞여 있고, `finSnapshotKind()` 만이 이를 판별합니다.
버전 표시가 없는 기록을 무조건 옛날 것으로 취급하면 **비교 가능한 과거 이력을 버리게** 되고,
부동산을 등록한 날이 시장이 급등한 날처럼 보입니다.

### 2-6. 순자산 계산을 앱과 배치 중 한쪽만 고치기

순자산 정의는 이제 **두 곳**에 있습니다 — 앱의 `script.js updateNetWorthSnapshot` 과
배치의 `scripts/net_worth_snapshot.py build_entry`. 같은 `netWorthHistory` 배열에
번갈아 기록되므로, 한쪽만 고치면 **같은 그래프 위에 기준이 다른 점이 섞입니다.**
그러면 순자산 변화 분석(브리지)의 '설명되지 않는 차이'가 통째로 왜곡됩니다.

한쪽을 고치면 반드시 다른 쪽도 같이 고치고,
`scripts/tests/test_net_worth_snapshot.py` 가 두 결과를 대조해 지킵니다
(그 대조는 node 를 못 돌리면 로컬에서만 SKIP 되고 **CI 에서는 실패**합니다 — 1-7 참조).

| **GitHub Actions 워크플로** | 워크플로 파일이 깨지면 **잡이 하나도 안 만들어지고** 즉시 실패한다. 로컬 `npm test` 는 이 파일을 실행하지 않는다 | PR 을 열어 CI 를 **실제로 돌린다**. 실행 목록에서 이름이 `품질 검사` 로 뜨는지 확인 — 파일 경로(`.github/workflows/quality.yml`)로 뜨면 파싱 실패다 |
| **모바일 레이아웃** | 화면 밖으로 밀린 요소는 `overflow-x:hidden` 에 잘려 **없는 것처럼** 보인다. 금액이 `200,000` → `200` 으로 읽히는 식 | 인라인 고정 폭은 이제 `test_layout_guards.mjs` 가 잡는다. 그 밖의 겹침·잘림은 브라우저를 **390px 폭**으로 줄여 눈으로 본다 |
| **CDN 라이브러리 로드 실패** | 정상 환경에서는 재현되지 않는다 | 사용 지점의 가드 누락은 이제 `test_layout_guards.mjs` 가 잡는다. 실제 동작은 네트워크를 막고 열어 본다 — 차트만 없어야 하고 자산·순자산·배당은 정상이어야 한다 |
| **터치 상호작용** | 마우스로는 재현되지 않는다. 브라우저가 탭 뒤에 **가짜 마우스 이벤트**를 흉내 내며, 그게 방금 연 설명을 즉시 닫아버린다 | 실제 터치 기기 또는 개발자도구의 터치 에뮬레이션으로 탭해 본다 |

### 실제로 있었던 일

`quality.yml` 에 이런 줄이 들어간 적이 있습니다.

```yaml
run: python -m pip install --only-binary=:all: numpy pandas
```

`:all:` 뒤의 **콜론+공백**이 YAML 문법에 걸려 파일 전체가 읽히지 않았고,
**품질 검사가 약 90분 동안 한 번도 실행되지 않았습니다.** 그동안 `npm test` 는 계속 초록이었습니다.
지금은 `scripts/tests/test_workflow_yaml.mjs` 가 이 패턴을 막습니다.

### 경보는 '진짜 신호'만 빨갛게 합니다

`세금·증여 공식 근거 점검`은 매일 law.go.kr 의 17개 조문을 읽어 문구가 바뀌었는지 봅니다.
2026-09-05 부터 **17개가 전부 timeout** 나기 시작했고, 그때마다 실행이 빨갛게 끝났습니다.

이게 왜 문제냐면, 빨간 X 의 뜻이 두 가지로 섞이기 때문입니다.

- **세법이 바뀐 것 같다** → 지금 확인해야 합니다
- **사이트에 접속이 안 된다** → 할 수 있는 게 없습니다

접속 장애가 며칠 이어지면 같은 빨간 X 가 쌓이고, 사람은 그걸 무시하게 됩니다.
그러다 그 사이에 낀 **진짜 변경**을 지나칩니다. 경보가 많아질수록 경보가 무의미해집니다.

그래서 `scripts/check-tax-rule-sources.mjs` 의 종료 코드로 둘을 나눴습니다.

| 코드 | 뜻 | 실행 결과 |
|---|---|---|
| `0` | 전부 정상 | 초록 |
| `1` | 매니페스트 오류 · 변경 의심 · **일부** 출처만 실패 | **빨강** |
| `2` | **한 곳도 못 읽음** (접속 장애) | 경고 + 검토 이슈 |

`2` 여도 검토 이슈는 그대로 열리므로 사실이 묻히지는 않습니다.
**이 구분을 없애지 마세요** — 없애면 위의 상태로 되돌아갑니다.

### 예약 실행 시각은 여유를 두고 잡습니다

GitHub 의 예약 실행(`schedule`)은 공용 스케줄러라 **몇 시간씩 밀립니다.**
실측 10회(2026-09-06~15) 지연은 **중앙값 약 4시간 56분, 최악 6시간 44분**이었습니다.
2026-09-14 실행은 UTC 14:24 = **KST 23:24** 로, 자정 경계까지 **36분**밖에 남지 않았습니다.
설계 여유(7시간 20분)의 92% 를 쓴 셈인데, 결과는 모두 `success` 라 실패 알림으로는 절대 드러나지 않습니다.

이게 왜 위험하냐면, 기록하는 날짜가 **실행 시각의 KST 날짜**였기 때문입니다.
지연이 KST 자정(= UTC 15:00)을 넘기면 그날 항목이 다음 날짜로 찍히고,
다음 날 실행이 같은 날짜를 덮어써 **하루가 통째로 빕니다** — 이 배치가 없애려던 공백이 그대로 생깁니다.

그래서 두 겹으로 막습니다.

1. 실행 시각을 KST 16:40(UTC `40 7`)으로 당겨 경계까지 7시간 20분의 여유를 뒀습니다.
   **이 시각을 늦추지 마세요.** 장 마감은 KST 15:30 이라 더 당길 여지도 조금 있습니다.
2. 예약 실행은 `--anchor-utc 07:40` 으로 **'직전 예정 시각의 KST 날짜'** 를 기준일로 씁니다
   (`scheduled_kst_date`). 20시간이 밀려도 날짜가 맞습니다. 여유만으로는 언젠가 넘기기 때문입니다.
   **수동 실행에는 앵커를 넘기지 않습니다** — 손으로 돌렸는데 어제 날짜가 찍히면 더 혼란스럽습니다.

`build_entry` 는 날짜를 인자로 받으므로 이 변경은 계산에 손대지 않습니다 —
따라서 앱(JS)과의 대조 테스트는 그대로 유효합니다.

### 2026-09-07 화면 검토 보완

- **배당 조회 성공은 티커별로 확인한다.** 서버의 `verifiedTickers`만 성공 목록에 기록한다. HTTP 200이어도 내부 공급자 조회가 실패할 수 있다. 배당 원본 이력도 25개씩 나누고, 부분 실패 때 직전 이력을 보존하며 실패 목록을 7일 성공 캐시에 넣지 않는다. 확인된 빈 이력과 조회 실패는 다른 상태다.

## ETF 구성비와 변경 이력 (2026-09-09)

- **수집 성공과 전체 조회는 다릅니다.** KRX가 해외 종목의 비중을 비워 주는데 국내 종목·선물 몇 줄만 받아 성공으로 처리한 문제가 있었습니다. 비중이 빠진 주식 행이 있으면 대체 출처로 넘어가고, 현금·채권·선물·머니마켓은 주식 룩스루에서 제외합니다. 남은 주식 비중을 100%로 늘리지 않습니다.
- **조회 시각은 구성 기준일이 아닙니다.** 운용사 공시 기준일과 수집 시각을 나눠 기록합니다. 기준일을 알 수 없는 상위 종목 목록은 일부 자료입니다. 액티브 ETF는 2평일, 기타 ETF는 5평일 초과 시 지연 표시하며 거래소 휴일은 반영하지 않습니다. 일부·지연·이전 유지 자료가 있으면 중복 노출과 리스크 종합 판정은 잠정입니다.
- **구성비는 날짜별 관찰값입니다.** 최근 30개 출처·기준일별 스냅샷을 보관하고 같은 날짜의 수정 공시는 교체합니다. 늦게 도착한 과거 자료로 최신 날짜를 되돌리지 않습니다. 수집 실패 시 마지막 유효 자료의 날짜를 보존합니다. 과거 기록을 소급해서 만들지 않습니다.
- **빠진 종목이 항상 편출은 아닙니다.** 같은 출처의 전체 목록끼리만 편입·편출로 비교합니다. 일부 목록에서는 양쪽에서 확인된 종목만 비교하며, 출처가 다르면 비교를 보류합니다. 비중 차이에는 가격 변동도 섞이므로 매매량이나 실제 거래 시점을 뜻하지 않습니다.
- **ETF 비중은 같은 기준선에서 비교합니다.** 가로 막대를 나중에 3D 블록으로 교체하지 않습니다. 한국 주식은 회사명으로, 해외 티커는 회사명 옆에 한 번만 표시합니다. PC에서 나란한 두 카드는 같은 높이로 맞추고 종목 목록은 좁은 행 간격과 페이지 구분을 유지합니다.
- **비중의 분모를 구분합니다.** 소유주 전체 포트는 그 사람의 주식·ETF·가상화폐·금·현금 평가액 합계이며 부동산·부채는 제외합니다. ETF 평가액을 분모에 한 번만 넣고, 해당 ETF 평가액 × 편입 종목 공시 비중을 간접 노출로 계산합니다. 여러 계좌는 소유주 안에서 합산하며 다른 소유주의 자산을 분모에 섞지 않습니다. 별도로 해당 종목 보유분만 100%로 놓은 직접·간접 비율도 표시합니다. 일부·지연·미조회 자료를 확정된 0%로 표시하지 않습니다.
- **시각화는 원장과 분리합니다.** ETF 탐색은 실제 자산을 수정하지 않으며 기존 리스크 룩스루는 같은 소유주의 직접 보유 종목과만 교차합니다. 다른 화면의 3D는 화면 밖에서 쉬고, 페이지를 떠나면 자원을 해제합니다.

- **완전한 출처를 부분 출처보다 먼저 씁니다.** 해외 ETF 는 stockanalysis → yfinance → 티커 별칭 순입니다. yfinance 는 `funds_data.top_holdings` 를 쓰므로 **정의상 상위 10종목만** 줍니다. 이걸 앞에 두면 성공하는 순간 체인이 끊겨 전체 바스켓을 영영 받지 못합니다. 실제로 DRAM 이 3종목(주식비중 40.7%), SPYM·1629 가 10종목으로 굳어 룩스루 간접 노출이 통째로 축소돼 있었습니다. 국내 분기(FunETF → KRX → …)와 같은 원칙입니다.
- **`coverage='full'` 은 출처 이름이 아니라 근거로 정합니다.** 예전에는 출처 이름 목록에 있으면 무조건 full 이었습니다. 지금은 `collect_one` 이 다섯 번째 값으로 완전성을 돌려주고 그것만이 근거입니다. stockanalysis 는 응답이 전체 종목 수를 스스로 밝히고 그 수가 읽은 행 수와 같을 때만 full 입니다. **기준일이 있다고 완전한 목록인 것은 아닙니다** — 상위 N 개 목록에도 날짜는 붙을 수 있으므로 둘을 함께 요구합니다.
- **자리표시자는 종목이 아닙니다.** 운용사 표의 코드 칸에는 현금·기타자산 행에 `--` 나 `-` 가 자주 옵니다. 영숫자가 하나도 없는 코드는 티커로 받아들이지 않습니다. stockanalysis 가 1순위가 되면서 이 행이 그대로 주식으로 들어올 수 있게 됐기 때문입니다.
- **단일 종목 레버리지 ETF만 배수로 해석합니다.** 지수형(QLD 등)은 스왑 바스켓을 배수로 추론하면 안 되지만, 상품명에 기초자산이 **하나로 명시된** 단일 종목 ETF(`T-REX 2X Long BMNR`)는 추론이 아니라 정의입니다. 단일 종목 발행사이면서 기초자산이 지수 심볼이 아닐 때만 해석하고, 인버스는 음수 노출이라 해석하지 않습니다(그쪽은 레버리지·인버스 노출도 카드가 담당). 해석된 상품은 '미조회 ETF' 각주에 넣지 않습니다.

## 현금 통화 확장 (2026-09-16)

- **지원 통화 정의는 한 곳뿐입니다.** `script.js` 의 `CURRENCY_META`(기호·현금 소수 자릿수·국기)와 그 목록인 `CASH_CURRENCIES`. 예전에는 `cur==='USD'?'$':(cur==='JPY'?'¥':'₩')` 같은 3항 분기가 파일마다 흩어져 있어서, 통화를 하나 늘릴 때마다 기호·소수점·국기 중 몇 군데를 반드시 빠뜨렸습니다. 실제로 **호주달러 예수금에 태극기가 붙는** 형태였습니다(비 USD/JPY 를 전부 'KR' 로 봤기 때문). `fixAssetCurrencies` 의 allow-list 도 이 목록을 그대로 씁니다 — 배열을 따로 적으면 둘이 갈립니다.
- **지원 통화에는 반드시 환율 시드값을 둡니다.** `RATES` 에 항목이 없으면 `RATES[cur]||1`·`cbRate` 경로가 **조용히 1:1 로** 환산해 A$1 이 ₩1 이 됩니다(약 950배 오차). 그래서 시드를 두고, 조회에 실패해도 **지우지 않습니다** — 지우면 다시 1:1 로 떨어집니다. 신선도는 `_priceStale` 로만 드러냅니다.
- **배치는 계산 규칙을 바꾸지 않고 기록 직전에 막습니다.** `asset_value_krw` 의 `rates.get(cur,1)` 은 앱의 `RATES[cur]||1` 과 같아야 하므로(둘이 갈리면 같은 그래프에 기준이 다른 점이 섞입니다) 그대로 두고, `missing_rate_currencies` 로 **보유 통화의 환율이 하나라도 없으면 스냅샷을 남기지 않습니다.** A$1 을 ₩1 로 적은 항목이 영구 이력에 남는 것이 더 나쁩니다. 금은 `curP` 가 이미 원화라 제외합니다.
- **테스트의 예외 처리는 위치에 의존하면 안 됩니다.** `test_dividend_tax.mjs` 의 연도 하드코딩 검사가 `'예전에는'` 이 든 **첫 줄 하나만** 지우고 있어서, 앞쪽에 같은 단어가 든 주석이 하나 생기자 정작 검사 대상 줄이 남아 엉뚱하게 실패했습니다. `/gm` 으로 모두 지웁니다.

## 리스크 지표 보강 (2026-09-16)

- **레버리지를 변동성에 반영합니다.** `CB_VOL` 은 자산군 상수라 QLD(2배 QQQ)도 일반 미국 ETF와 똑같이 22% 로 잡혀 위험이 과소평가됐습니다. `cbLeveragedInverseMeta` 가 이미 배수를 알고 있으므로(상품명의 배수 → 티커 표 → 레버리지 2배·인버스 1배) 그만큼 기여분을 키웁니다. 인버스는 방향이 아니라 변동 폭만 쓰므로 절대값 배수입니다. 종목별 실제 변동성과 상관관계는 여전히 반영하지 않으며, 툴팁이 그 한계를 밝힙니다.
- **ETF 간 중복도는 기존 룩스루를 바꾸지 않고 따로 냅니다.** 룩스루는 '직접 보유 회사와 겹치는 부분'만 셉니다(그 규칙은 유지). 그래서 NVDA 를 직접 안 들고 두 ETF 로만 담고 있으면 중복도가 0 으로 보입니다. 테마가 몰린 포트폴리오에서는 섹터 분류가 흩어져 있어도 실제로는 같은 회사에 겹쳐 노출되므로, `cbEtfCrossOverlap` 이 직접 보유 여부와 무관하게 '두 개 이상의 ETF 에 동시에 들어 있는 종목'을 셉니다.
- **소유주 경계와 미확인 처리는 룩스루와 같습니다.** 서로 다른 소유주의 ETF 를 한 종목으로 합치지 않고, 구성종목을 못 받았거나 잠정인 ETF 는 합산에서 빼고 그 이름을 남겨 '일부 미확인'으로 표시합니다. 확인되지 않은 자료로 0% 를 단정하지 않습니다.
- **카드 그리드의 행 수를 고정하지 않습니다.** 예전에는 4행 고정이라 보조 진단을 9번째로 추가하면 화면에서 조용히 사라졌습니다. 이제 행 수가 카드 개수를 따릅니다.

검증: `test_risk_page.mjs` 의 배수 변동성·중복도·소유주 경계·미확인 처리 테스트, `test_ui_followups.mjs` 의 위젯 개수·그리드 계약.

## 투자자산 추이 (2026-09-16)

- **모으기만 하고 그리지 않는 데이터를 남기지 않습니다.** 순자산 스냅샷 배치는 매일 돌고 있었는데, 메뉴를 7개로 통합하며 한눈에 보기와 재무상태표 화면이 사라져 **그리는 화면이 하나도 없는 상태**였습니다. 추이 차트는 이제 **투자 분석 > 성과**의 '투자자산 추이' 카드에 있습니다.
- **순자산이 아니라 투자자산입니다.** 부동산·부채는 대시보드에서 관리하지 않기로 했으므로 스냅샷의 `portfolio` / `portfolioByOwner` 만 씁니다. `portfolio` 를 안 남긴 과거 항목은 `total − 기타자산 + 부채` 로 정확히 역산하고, 구성요소마저 없으면 버립니다(그 `total` 이 투자자산인지 순자산인지 알 수 없기 때문입니다). 이 기준은 재무상태표 유무와 무관하게 v1·v2 가 바로 비교되므로 **순자산 기준보다 기록 커버리지가 넓습니다.**
- **백캐스트와 실제 금액을 같은 화면에서 구분합니다.** 위쪽 수익률 차트는 지금 비중을 과거에 소급한 값이라 실제 수익률이 아니고, 아래 카드는 매일 기록된 실제 평가액이라 매수·매도·입금이 그대로 섞입니다. 카드는 '수익률이 아니다'라는 사실과 부동산·부채 제외를 함께 밝힙니다. 성과 비교의 각주가 가리키던 '가족 재무상태표 > 순자산 추이'는 없는 화면이었고, 이제 이 카드를 가리킵니다.
- **기간·소유주 상태는 카드가 따로 기억합니다.** 성과 페이지에는 소유주 필터가 없습니다(소유주별 수익률을 라인으로 동시에 보여주는 화면입니다). 그래서 카드가 `_finNwTf` / `_finNwOwner` 를 자체 보유하고, 재렌더 뒤 포커스는 `cbRestoreFilterFocus` 로 되돌립니다.

- **값을 쓰는 화면이 있으면 바꾸는 자리도 있어야 합니다.** 현금 안전판 '목표 개월수'(`cashTargetMonths`)는 리스크 진단과 투자 계획이 계속 쓰는데, 그 값을 바꾸는 `finSaveCashTarget` 은 사라진 재무상태표 안에만 있어 **저장된 값에 굳어 있었습니다.** 지금 자리는 **투자 계획 > 목표**의 현금 안전판 패널입니다(`finGoalContext`) — 그 화면이 이미 같은 값을 '월 필수지출 기준 몇 개월'로 보여주고 있어 바로 옆이 제자리입니다. 모바일은 읽기 전용이라 `finMobileNote` 로 대신합니다.

검증: `test_finance_features.mjs` 의 투자자산 기준 시리즈·카드 문구·현금 안전판 목표 저장 테스트.

## ETF 공식 보유명세 파일 (2026-09-16)

- **조회 순서를 바꿨는데 안 고쳐지면, 순서가 원인이 아니었던 것입니다.** `stockanalysis` 를 `yfinance` 앞으로 옮겨 놓고 GitHub Actions 에서 실제로 돌려 봤더니 1629·SPYM·DRAM 이 그대로였습니다(10·10·3종목). 로컬에서 막힌 것이 아니라 그 소스가 이 세 펀드를 주지 않는 것이었습니다. **추측 대신 CI 한 번을 돌린 것이 판단을 끝냈습니다.** funetf.co.kr 은 국내 상장 ETF 카탈로그라 해외 펀드에는 애초에 해당이 없었습니다.
- **그래서 운용사 공시 파일을 리포에 넣습니다.** `data/etf_sources/` + `scripts/etf_sources.py`. 1629 → 126종목, SPYM → 503종목, DRAM → 15종목으로 복구됐습니다. 등록은 `index.json` 이고, **검증에 하나라도 걸리면 조용히 기존 체인으로 폴백합니다** — 지금보다 나빠지는 경로가 없어야 파일을 넣을 수 있습니다.
- **`coverage='full'` 의 근거는 여전히 '전부 받았다는 근거'입니다.** 출처가 파일이라는 사실 자체는 근거가 아닙니다. 파일의 비중 합계가 순자산 97~103% 를 설명할 때만 full 입니다 — 상위 10종목 목록은 이 밴드에 들어올 수 없습니다.
- **서드파티 라이브러리를 늘리지 않습니다.** 수집기는 모듈 최상단에서 서드파티를 import 하지 않고 CI 는 numpy/pandas 만 설치합니다. xlsx 는 `zipfile`+`ElementTree`, PDF 는 콘텐츠 스트림을 직접 읽습니다. 그 PDF 파싱에서 한 번 넘어졌습니다 — `BT…ET` 를 정규식으로 찾으면 본문의 `DRAM **ET**F Holdings` 가 먼저 걸려 블록이 잘립니다. 줄 단위로 읽고 괄호 깊이를 셉니다.
- **기초자산이 명시된 스왑은 그 종목의 노출로 셉니다.** QLD 금지 규칙은 스왑 바스켓 내용을 **알 수 없어서** 둔 것이라 여기에 해당하지 않습니다. DRAM 은 스왑 행의 Identifier 첫 토큰이 기초자산의 CUSIP/SEDOL 이고 그 값이 **같은 표의 현물 주식 행과 일치**합니다. 이 규칙이 없으면 마이크론 실질 노출이 25.34% 인데 화면에 0.42% 로 보입니다. 다만 이건 `parse_tema_pdf` 안에서만이고, 공용 `NON_EQUITY_NAME_RE` 의 스왑 제외는 그대로입니다.
- **총 노출이 100%를 넘을 수 있습니다.** DRAM 은 100.19% 입니다 — 국채·MMF 담보 위에 스왑을 얹은 구조라 사실입니다. 100%로 재정규화하지 않습니다.
- **고정 파일이므로 기준일이 멈춥니다.** 1629 는 `2026-08-31` 이라 이미 '기준일 지연'으로 표시되는데, 그게 맞는 표시입니다. 숨기지 않습니다. 갱신은 같은 경로에 새 파일을 덮어쓰면 됩니다.
- **원격 체인을 검증하는 테스트는 파일을 꺼 둡니다.** `test_foreign_sources.py` 가 DRAM·SPYM 을 예시 코드로 쓰고 있어서, 파일이 붙자 원격 순서를 볼 수 없게 됐습니다. `_RemoteChainCase` 가 `fetch_local_source` 를 막고, 파일 쪽 동작은 `test_etf_sources.py` 가 따로 고정합니다.

## 성과·리스크 화면 정리 (2026-09-16)

- **서로 다른 필터를 한 덩어리로 붙이지 않습니다.** 투자자산 추이의 소유주 버튼과 기간 버튼이 한 `.owner-tabs` 안에 이어 붙어 있어서 `전체 본인 아내 자녀1 아버지 1M 3M 6M 1Y 전체` 가 한 줄로 흐르고 **'전체'가 두 번** 나왔습니다. 이제 `.fin-trend-tabs` 안의 별도 그룹 둘이고 사이에 구분선이 있습니다.
- **그래프 위에 어디를 가리키는지 표시합니다.** 툴팁만 뜨고 차트에는 아무 표시가 없어 툴팁 숫자가 어느 점의 것인지 알 수 없었습니다. 성과 비교 차트의 `#cb-perf-guide` 와 같은 세로 점선에 지점 마커를 더했습니다. **가이드를 SVG 안에 둡니다** — 성과 차트처럼 HTML 오버레이로 하면 `viewBox` 의 padL/padR 을 퍼센트로 다시 계산해야 하는데, 여기서는 렌더 시점에 이미 정확한 좌표를 알고 있습니다. 터치는 기존 `data-chart-hit="finNw:<i>"` 문서 위임이 그대로 이어집니다.
- **Y축 눈금을 6단계로 세분합니다.** 4단계는 한 칸이 수천만 원이라 선이 어느 금액대에 있는지 읽히지 않았습니다.
- **리스크 진단에서 '현금 유동성 커버리지'를 뺐습니다.** 보조 진단이 9개가 되면서 카드 한 장이 새 행을 열고 있었고, 같은 숫자를 투자 계획 > 목표가 더 넓은 맥락(투자자산·월 적립액과 나란히)으로 보여줍니다. 카드만 지우고 끝내지 않고, **그 카드만 쓰던 인사이트 `control` 슬롯과 `.cb-risk-insight-control` CSS 도 함께** 지웠습니다.
- **컴팩트화는 폭이 아니라 여백입니다.** 카드 패딩·`min-height`·그리드 `gap` 을 줄였고, 점수 카드 칼럼 폭(`minmax(300px,320px)`)은 그대로 둡니다 — 그 값은 점수 막대가 눌리지 않게 하려고 앞서 정한 것이고 테스트가 고정하고 있습니다.

## 리밸런싱·적립식 여백 정리 (2026-09-16)

- **같은 작업에 쓰는 입력은 같은 흐름에 둡니다.** 목표 비중 자산군 6개가 2열 그리드에 있고 허용 편차·목표 저장이 **그 아래 별도 줄**이라, 저장 버튼 한 개 때문에 한 줄이 통째로 여백이었습니다. 이제 셋 다 `.fin-target-inputs` 안이고, 그리드가 `repeat(auto-fit,minmax(156px,1fr))` 라 폭에 맞춰 흐릅니다(넓은 화면 4행 → 2행). 빈 `.fin-target-actions` 규칙도 함께 지웠습니다.
- **적립식 목록에서 '수정' 버튼을 뺐습니다.** 같은 편집을 상단의 보유 종목 선택으로도 하고 있어 칼럼 하나가 그 버튼만을 위해 94px 을 쓰고 있었습니다. 토글만 남기고 46px 로 줄였으며, 헤더도 `규칙 관리` → `관리` 로 우측 정렬했습니다. 행 `min-width` 도 같은 48px 만큼 줄여야 합니다 — 안 줄이면 표가 필요 없이 가로로 넘칩니다.
- **호출부가 사라진 함수는 같이 지웁니다.** `cbDcaOpenHolding` 은 그 버튼만 부르던 함수라 함께 제거했습니다. 빈 함수를 남기면 다음 사람이 '쓰는 데가 있나 보다' 하고 되살립니다.

## 월별 현금흐름 요약 (2026-09-16)

- **입력 위젯이 두 열을 다 쓰고 있어 우측 절반이 통째로 빈 여백이었습니다.** 입력부를 좌측 열로 내리고 우측 첫 행에 '선택 달 요약'을 넣었습니다. 좁아진 열에서 입력 줄은 **가로 스크롤 대신 접힙니다** — 스크롤로 두면 오른쪽에 필드가 더 있다는 것조차 보이지 않습니다.
- **요약은 새 계산을 하지 않습니다.** `renderCashFlow` 가 이미 구한 `tIn`/`tOut`/`expByCat` 을 그대로 받습니다. 같은 숫자를 두 번 계산하면 언젠가 갈립니다.
- **저축률과 순현금흐름은 다른 숫자입니다.** 순현금흐름은 통장에 남은 돈(`tIn − tOut`)이고, 저축률은 `'저축/투자'` 지출을 소비에서 **되돌린** 뒤의 비율입니다. 그 카테고리는 통장에서 빠져나가도 자산으로 옮겨 간 돈이라 `finMonthlyFixedCost` 와 `finNetWorthBridge` 가 이미 같은 이유로 제외하고 있습니다. 여기서만 다르게 세면 같은 화면이 서로 다른 '지출'을 말하게 됩니다. 툴팁이 그 차이를 밝힙니다.
- **수입이 0인 달은 저축률을 내지 않습니다**(`—`). 0 으로 나눈 값을 0% 로 보여주면 '한 푼도 안 모았다'로 읽힙니다.
- **미분류 자동이체 안내를 이 화면에 둡니다.** 분류해야 월 필수지출과 현금 안전판이 맞게 나오는데, 분류하는 자리(고정비 관리)가 바로 옆 탭입니다. 건수·월 환산액은 `finMonthlyFixedCost` 의 `pendingCount`/`pendingMonthly` 를 그대로 씁니다.

검증: `test_ui_followups.mjs` 의 요약 카드 계산·레이아웃 계약.

## 백테스트와 입력 배치 (2026-09-11)

- 세부 탭은 상단 소유주·기간 버튼 왼쪽에 놓는다. 홈 하단 바로가기는 제거하고, 섹터 펼침 목록은 해외 티커·한국/일본 회사명을 쓴다. 적립식 등록·수정은 보유 목록으로 연결하고 계획 페이지는 일정 확인에 쓴다.
- 과거 백테스트는 종목 검색 후 선택한 종목만 계산한다. 마감된 일별 수정주가가 누락되면 계산을 중단한다. 첫 조회일 초기 투자, 다음 달부터 월 첫 거래일 적립, 매수 수수료 차감을 적용한다. 통화와 실제 조회 구간을 표시하고 환율·세금·매도 비용은 포함하지 않는다. CAGR·최대 낙폭은 종목 수정주가 기준이며 납입원금 대비 손익률과 구분한다. 이전 검색/설정 응답은 새 결과를 덮지 않는다. 실제 원장이나 주문에는 쓰지 않는다.
- 대표 배분은 원문 링크가 있는 비교 자료다. 현재 자산군은 시장별 분류이므로 주식/채권 비율을 자동 대입하지 않는다. 목표별 월 필요액은 수익률 0% 가정이며 서로 겹치는 목표를 합산하지 않는다.

검증: `test_backtest.mjs`의 납입·수수료·분할 수정·낙폭·누락 가격 검증, 재무 회귀 테스트 및 PC 입력 행/검색 결과 화면 확인.

## 종목 요약·상단 조작·배당 추정 (2026-09-14)
- 홈의 종목 요약은 현재 검색·소유주 범위 안의 종목만 선택한다. 비중 분모는 검색 전 소유주 범위다. 구성원 비교의 상단 소유주 선택은 표와 자산군 위젯에 함께 적용된다.
- 제목과 설명은 같은 줄, 세부 메뉴와 소유주 버튼은 같은 그룹에 둔다. 현금 흐름도 같은 버튼 서식을 쓴다. ETF 중복 제목은 제거한다. 공개된 사이드바 GOLD 시세만 금액 가리기에서 제외하고 보유 금 평가액은 계속 가린다.
- 90일 배당은 공시 확정 일정이 아니라 과거 반복 패턴·현재 수량으로 추정한 세전 금액이다. 과거 지급일을 확정일로 표시하지 않는다. 날짜 미정은 15일을 가정하지 않고 기간과 겹치는 달을 표시한다. 경계 월 일부는 90일 밖에 지급될 수 있음을 밝힌다. 이 표시 수정은 실제 현금 흐름 기록을 변경하지 않는다.

## ETF 점검·시세 확인 안내 (2026-09-14)
- 페이지의 국내 ETF는 FunETF를 우선 조회하며 실패 시 제한 시간 안에서 TIME 지원 종목과 Zeroin 1회 조회를 시도한다. 정기 배치의 재시도 기본값은 유지한다. 개별 재조회는 보유 ETF만 가능하고 중단된 이전 요청은 조회 중 상태에 남기지 않는다. 출처·기준일·불완전 사유를 보여주고 마지막 정상 자료를 보존한다.
- 리스크 요약은 고정 폭으로 옆 카드에 침범하지 않으며 우측 카드 묶음과 하단을 맞춘다. 추가 점검 내용도 같은 소유주의 기존 규칙 결과에서 만든다.
- 데이터 상태의 시장 시세 안내는 미확인 종목, 시세 재조회, 코드·통화 대조, 증권사 확인 순서를 제공한다. 요청 성공과 실시간 체결가는 다르다.
