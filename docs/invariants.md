# 건드리면 안 되는 것

이 저장소를 고치기 전에 한 번 읽는 문서입니다.
여기 적힌 것들은 **한 번씩 실제로 사고가 났던 자리**이고, 대부분은 화면이 멈추는 게 아니라
**틀린 숫자를 아무 일 없다는 얼굴로 보여주는** 방식으로 터집니다. 그래서 눈에 잘 안 띕니다.

- 규칙을 기계가 지키는 형태로 적어 둔 곳: `CLAUDE.md` 의 `Cross-cutting domain rules` 절
  (Claude Code 가 매 세션 자동으로 읽습니다)
- 이 문서: 같은 내용을 **사람이 읽고 판단할 수 있게** 풀어 쓴 것 + 테스트가 못 잡는 영역 정리

## 0. 수정을 요청할 때 붙일 문장

다음에 Claude·codex 등에게 이 저장소 작업을 시킬 때, 아래 문단을 그대로 복사해 붙이면 됩니다.

> 작업 전에 `docs/invariants.md` 와 `CLAUDE.md` 의 Cross-cutting domain rules 를 먼저 읽어라.
> 거기 적힌 규칙을 어겨야만 요청을 처리할 수 있다면, 임의로 고치지 말고 먼저 나에게 알려라.
> 같은 성격의 코드가 다른 곳에도 있는지 `grep` 으로 먼저 세고 나서 고쳐라 — 이 저장소는
> 한쪽만 고친 '반쪽 수정' 때문에 같은 버그가 재발한 적이 있다.
> 끝나면 `npm test` 를 돌리고, 그것만으로 확인되지 않는 영역(아래 3번)은 따로 확인했다고 말해라.

## 1. 절대 하지 말 것 — 돈과 기록이 걸린 것

### 1-1. 세금·증여 숫자를 코드에 직접 쓰지 않는다

세율·공제액·기준금액은 **`tax-rules.js` 한 파일에만** 있습니다.
계산하는 쪽은 `assetTaxRuleValue` / `_taxRuleValue` 를 통해서만 읽습니다.

편해 보인다고 `0.154` 같은 숫자를 계산식에 직접 적으면, 법이 바뀔 때 어디를 고쳐야 하는지
아무도 모르게 됩니다. 화면에는 계속 옛날 세율로 계산된 금액이 나옵니다.

세금 값을 바꿀 때는 값·출처·가정·`verifiedAt`·`nextReviewAt`·버전을 **한꺼번에** 고치고
`docs/tax-rule-changelog.md` 에 기록을 남긴 뒤 `npm run check:tax-rules` 를 돌립니다.

### 1-2. 배당세 계산을 새로 만들지 않는다

배당 세후 금액을 구하는 엔진은 `script.js` 의 `allocateDividendTax` **하나뿐**입니다.
배당 이력·캘린더·계좌 진단·가계부 자동 등록이 전부 이 함수를 거칩니다.

새 화면을 만들면서 "여기서만 간단히" 세금을 계산하면 화면마다 다른 금액이 나옵니다.
특히 ISA 공제를 종목별 반복문 안에서 적용하면 **세금이 통째로 사라집니다** — 공제를
종목 수만큼 중복 적용하기 때문입니다. 반드시 보유 종목을 한꺼번에 넘겨야 합니다.

> ISA 계산은 연간 현금흐름 **참고치**입니다. 실제 ISA 세금은 계좌 만기·해지 때
> 가입 기간 전체 손익으로 정산되므로, 화면 표기에서 '연간 현금흐름 참고' 라벨을 떼면 안 됩니다.

### 1-3. 티커 상한(25 / 20)을 올려서 해결하지 않는다

서버는 요청 하나에 담긴 종목 수를 검사합니다. 시세·배당은 **25개**,
성과 비교 벤치마크는 **20개**가 상한입니다. 넘기면 서버가 그 요청을 **통째로 거부**합니다.

증상: 보유 종목이 늘어난 순간 **시세·배당·성과 라인이 한꺼번에 비고**,
데이터 상태가 영구히 '확인 필요'로 남습니다.

이건 보안상 입력 검증이라 **올려서 고치는 게 아니라** 나눠 보내서 고칩니다.
`_chunkTickers()` 로 잘라 보내고 결과를 합칩니다. 일부만 실패하면 성공분은 반영하되
**실패를 숨기지 않고** 보고해야 합니다.

### 1-4. 원장을 불러오지 못한 상태에서 저장하지 않는다

`window._kvLoadState` 가 `ready` 가 아니면 저장 함수들이 쓰기를 거부합니다.
이 방어를 빼면 **불러오기 실패 → 빈 화면 → 그 빈 상태를 서버에 저장** 순서로
실제 자산 기록이 지워집니다.

### 1-5. 날짜 키를 `toISOString()` 으로 만들지 않는다

`toISOString()` 은 세계 표준시(UTC)라 한국에서는 **오전 9시 이전에 어제 날짜**를 돌려줍니다.
반드시 `finance.js` 의 `finLocalDateKey()` 를 씁니다.
순자산 스냅샷 키, 현금 흐름 기간, "오늘 제외" 판정이 전부 하루씩 밀립니다.

### 1-6. 배당 자동 가계부 기록을 함부로 지우지 않는다

`autoAddDividendCashFlow` 는 앱이 만든 배당 기록을 지울 수 있습니다.
지워도 되는 근거는 **확실한 것 세 가지뿐**입니다 — 종목을 팔았거나, 사용자가 지웠거나,
**조회에 성공한** 일정에 그 달 지급이 없거나.

내장 DB 폴백(`_divSource === 'db'`)은 **조회가 실패했을 때도 나타납니다.**
이걸 삭제 근거로 삼으면 **네트워크가 한 번 끊긴 것만으로 실제 배당 기록이 사라집니다.**

### 1-7. 테스트를 끄거나 건너뛰어서 초록으로 만들지 않는다

이 저장소에는 **CI 에서 조용히 건너뛰던 테스트가 한동안 방치된 적**이 있습니다
(`test_benchmark_columns.py` — pandas 미설치 시 자기가 SKIP). 지금은 CI 환경에서
건너뛰면 실패하도록 바꿔 뒀습니다. 이 장치를 되돌리지 마세요.

## 2. 조용히 틀린 숫자를 보여주게 되는 것

### 2-1. 소유주 필터를 통과시키지 않은 계산

소유주 탭(본인/아내/자녀1/아버지)을 누르면 **그 화면의 모든 숫자**가 따라가야 합니다.
가구 전체 합계가 한 칸이라도 새어 나오면 사용자는 그걸 그 사람의 자산으로 읽습니다.

구조상 소유주별로 나눌 수 없는 숫자(예: 순자산 브리지 — 가구 단위 스냅샷만 존재)는
계산을 억지로 하지 말고 카드에 **"가구 전체"** 라고 표시합니다.

### 2-2. 데이터 신선도를 메모리 상태로 추론

"데이터 상태" 화면의 초록불은 **실제 조회 성공 기록(`finMarkFresh`)** 이 있을 때만 켜집니다.
`pfolioData.length >= 0` 같은 검사는 **항상 참**이라 영원히 꺼지지 않는 가짜 초록불이 됩니다.

세 가지 상태를 구분해야 합니다 — `ok`(조회 성공) / `warn`(조회 실패) / `pending`(아직 조회 안 함).
`pending` 은 오류가 아니므로 빨간색으로 칠하면 진짜 오류가 묻힙니다.

### 2-3. 배당 조회 완결성을 캐시 키 개수로 판정

`_divDataCache` 에는 **배당이 있는 종목만** 들어갑니다. 무배당 종목은 조회에 성공해도
행이 생기지 않습니다. 그래서 "캐시에 몇 개 있나"로 판정하면 **무배당 종목이 전부
'조회 실패'로 잡혀** 멀쩡한 화면에 경고가 뜹니다.

판정은 `window._divFetchCoverage` 의 verified 목록으로만 합니다.
판정할 근거가 아직 없으면 경고하지 말고 **'확인 중'** 으로 둡니다.

### 2-4. 배당 지급월 기본값을 두 군데서 다르게

API 가 지급월을 안 알려준 종목의 기본값은 `cbDefaultDivMonths` **하나만** 씁니다.

과거에 월별 막대만 "주기대로(연 1회면 12월)" 고치고 '다가오는 배당'은 분기 가정을
그대로 둔 적이 있습니다. 결과는 **같은 화면 안에서 두 위젯이 서로 다른 일정**을 그리는 것이었습니다.

### 2-5. 순자산 스냅샷을 구조 확인 없이 분류

과거 기록은 세 가지 모양이 섞여 있고, `finSnapshotKind()` 만이 이를 판별합니다.
버전 표시가 없는 기록을 무조건 옛날 것으로 취급하면 **비교 가능한 과거 이력을 버리게** 되고,
부동산을 등록한 날이 시장이 급등한 날처럼 보입니다.

## 3. `npm test` 가 초록이어도 안심하면 안 되는 영역

**이 절이 이 문서에서 가장 중요합니다.** 아래 네 가지는 로컬 테스트가 통과해도 깨져 있을 수 있습니다.

| 영역 | 왜 테스트로 안 잡히나 | 어떻게 확인하나 |
|---|---|---|
| **GitHub Actions 워크플로** | 워크플로 파일이 깨지면 **잡이 하나도 안 만들어지고** 즉시 실패한다. 로컬 `npm test` 는 이 파일을 실행하지 않는다 | PR 을 열어 CI 를 **실제로 돌린다**. 실행 목록에서 이름이 `품질 검사` 로 뜨는지 확인 — 파일 경로(`.github/workflows/quality.yml`)로 뜨면 파싱 실패다 |
| **모바일 레이아웃** | 화면 밖으로 밀린 요소는 `overflow-x:hidden` 에 잘려 **없는 것처럼** 보인다. 금액이 `200,000` → `200` 으로 읽히는 식 | 브라우저를 **390px 폭**으로 줄여 눈으로 본다. 특히 인라인 `style` 에 고정 폭이 있는 곳 |
| **CDN 라이브러리 로드 실패** | 정상 환경에서는 재현되지 않는다 | 네트워크를 막고 열어 본다. 차트만 없어야 하고, 자산·순자산·배당은 정상이어야 한다 |
| **터치 상호작용** | 마우스로는 재현되지 않는다. 브라우저가 탭 뒤에 **가짜 마우스 이벤트**를 흉내 내며, 그게 방금 연 설명을 즉시 닫아버린다 | 실제 터치 기기 또는 개발자도구의 터치 에뮬레이션으로 탭해 본다 |

### 실제로 있었던 일

`quality.yml` 에 이런 줄이 들어간 적이 있습니다.

```yaml
run: python -m pip install --only-binary=:all: numpy pandas
```

`:all:` 뒤의 **콜론+공백**이 YAML 문법에 걸려 파일 전체가 읽히지 않았고,
**품질 검사가 약 90분 동안 한 번도 실행되지 않았습니다.** 그동안 `npm test` 는 계속 초록이었습니다.
지금은 `scripts/tests/test_workflow_yaml.mjs` 가 이 패턴을 막습니다.

## 4. 두 번 이상 재발한 사고

| 영역 | 횟수 | 왜 재발했나 |
|---|---|---|
| **배당 현금흐름·세금** | 5회+ | 이 저장소에서 가장 자주 고쳐진 영역. 세금·캐시·삭제 근거·부분 실패가 얽혀 있다 |
| **CDN 로드 실패 가드** | 2회 | 처음 고칠 때 최상위 블록만 막고 `initDashboard` 안의 `new Chart` 를 놓쳤다 |
| **배당 지급월 기본값** | 2회 | 처음 고칠 때 월별 막대만 고치고 '다가오는 배당'을 놓쳤다 |

**공통 원인은 하나입니다 — 반쪽 수정.**
같은 성격의 코드가 다른 곳에도 있는데 한 군데만 고쳤습니다.

> **규칙**: 무언가를 고치기 전에 같은 패턴이 몇 군데 있는지 `grep` 으로 먼저 세고,
> 전부 고치거나 왜 한 곳만 고치는지 이유를 남긴다.

## 5. 규칙 ↔ 지키는 장치

'없음' 칸이 **사람이 눈으로 확인해야 하는 지점**입니다.

| 규칙 | 어기면 보이는 증상 | 막아주는 장치 |
|---|---|---|
| 세금 값은 `tax-rules.js` 단일 소스 | 화면마다 다른 세율 | `test_tax_rule_manifest.mjs`, `npm run check:tax-rules` |
| 배당세는 `allocateDividendTax` 단일 엔진 | ISA 세금이 0원으로 사라짐 | `test_dividend_tax.mjs` |
| 티커는 상한에 맞춰 나눠 전송 | 시세·배당·성과가 한꺼번에 빔 | `test_ticker_chunking.mjs` |
| 원장 로드 전 저장 금지 | 실제 자산 기록이 빈 값으로 덮임 | `test_data_loading_state.mjs` |
| 날짜는 `finLocalDateKey` | 오전 9시 이전 기록이 하루 밀림 | `test_finance_features.mjs` |
| 배당 기록 삭제는 확실한 근거만 | 네트워크 한 번 끊기면 기록 소실 | `test_dividend_tax.mjs` |
| 소유주 필터 전면 적용 | 남의 자산이 내 것으로 표시됨 | `test_snapshot_page.mjs`, `test_risk_page.mjs`, `test_lookthrough_owner_scope.mjs` |
| 신선도는 기록으로만 판정 | 영구 가짜 초록불 | `test_data_loading_state.mjs` |
| 워크플로 `run:` 값에 `": "` 금지 | CI 가 통째로 멈춤 | `test_workflow_yaml.mjs` |
| CDN 라이브러리는 가드 필수 | 앱 전체가 빈 화면 | `test_accessibility_static.mjs` (부분) |
| 터치 툴팁 유예 창 유지 | 폰에서 설명이 안 보임 | `test_accessibility_static.mjs` (부분) |
| 반응형 폭은 CSS 클래스로 | 모바일에서 금액이 잘려 **틀린 숫자로 읽힘** | `test_ui_followups.mjs` (기존 3곳만) |
| 새로 만드는 화면의 모바일 레이아웃 | 화면 밖으로 밀려 잘림 | **없음 — 390px 로 눈으로 확인** |
| 새로 추가하는 외부 라이브러리 | 로드 실패 시 앱 정지 | **없음 — 네트워크 차단 후 확인** |

## 6. 이 문서를 유지하는 법

- 새 불변조건이 생기면 **이 문서와 `CLAUDE.md` 를 같은 커밋에서** 함께 고칩니다.
  한쪽만 고치면 다음 사람이 어느 쪽을 믿어야 할지 알 수 없게 됩니다.
- 사고가 나서 고쳤다면, **왜 그게 사고였는지**를 여기 한 줄 남깁니다.
  규칙만 적으면 다음 사람이 "이건 필요 없어 보이는데" 하고 지웁니다.
- 5번 표의 '없음' 칸을 테스트로 채울 수 있으면 채우고, 표를 갱신합니다.
