# 가족 자산 관리

[Claude Design](https://claude.ai/design)에서 제작한 시안의 레이아웃과 테마를
그대로 구현하고, 기존 `asset_dashboard_claude-code` 앱의 실데이터(KV 자산, 시세·배당 API, 인증)를
연결한 버전입니다.

## 페이지 구성

사이드바는 **요약 / 분석 / 계획 / 기록·관리** 네 그룹으로 접히며, 접은 상태는 저장됩니다.

### 요약
1. **대시보드** — 가족 투자자산 헤더 + 일일손익/평가손익/연배당/리스크 배지, **이번 달 할 일**(목표 편차·현금 안전판·DCA·배당 일정·데이터 점검 바로가기), 자산 배분 도넛·섹터 집중도 바(클릭 시 소속 종목 펼침), 보유 자산 내역 표 + 종목 상세 패널
2. **구성원별 보유** — 구성원 카드(비중 바) 클릭 필터 + 보유 자산 표 + 소유주별 자산군 구성
3. **가족 재무상태표** — 투자자산 + 기타 자산(부동산·예적금·보험) − 부채 = 전체 순자산, **순자산 추이 차트**(일별 스냅샷 최대 365일, 기간·소유주 전환, 실제 MDD), 순자산 변화 분석(이전 순자산 + 순현금흐름 + 설명되지 않는 차이), 현금 안전판

### 분석
4. **성과 비교** — 소유주별 포트폴리오 vs S&P 500 · KOSPI (정규화 차트 + 기간별 초과수익·MDD 표). *현재 보유 비중을 기간 시작일부터 소급 적용한 백캐스트*이며 화면에 그렇게 표기됩니다
5. **리스크 진단** — 점수 링 + 규칙 카드 8종(집중도·가상화폐·섹터·변동성·현금·환노출·분산·레버리지) + 보조 진단 8종 + 종목 집중도 ETF 룩스루 차트
6. **배당 관리** — **세전/세후 전환**(계좌별 현금흐름 추정), 연간/월평균/YoC/배당성장률/집중도 카드, **입력된 일반계좌 배당 기준 금융소득 부분 근접도**, 월별 배당 캘린더, 종목별 배당 표(배당세 칼럼), 향후 90일 일정
7. **비중 차트** — Plotly 선버스트로 보유 비중 드릴다운

### 계획
8. **목표·리밸런싱** — 재무 목표 진행률(자산군·순자산 연동), 목표 비중 대비 편차 → 필요 조정액 → **월 DCA 보정안**, 계좌 배치 진단(실제 배당 세율 기준 절세 여력 금액)
9. **DCA 자동매수** — 규칙 토글, 다음 매수일·예상 처리 시점, 월 환산 배분
10. **가족 증여** — 자녀 정기증여(법정 연 3%를 월납으로 근사한 유기정기금 PV)와 부부 증여 계획, 실제 최근 10년 내역 확인 후 공제 규모 비교

### 기록·관리
11. **자산 내역** — 투자자산 CRUD + DCA 규칙 등록 (모든 화면의 원본)
12. **현금 흐름** — 월별 수입·지출 가계부 + 고정비 관리 (여기서 분류한 고정비가 현금 안전판 기준)
13. **양도소득세** — 월별 실현손익 기록/차트, 일반적인 해외주식 250만원 공제 → 지방세 포함 22%, ISA는 만기 정산 전 연간 현금흐름 참고치로 분리 표시

**데이터 상태**는 사이드바 푸터의 상태 줄에서 엽니다 — 항목별 출처·최근 확인 시각·상태를 한곳에서 보여주고, 카드마다 해당 소스만 다시 조회할 수 있습니다. 상태는 **정상 / 확인 필요 / 확인 전** 세 가지이며, 아직 조회하지 않은 것은 오류가 아니므로 푸터 점은 실패가 있을 때만 붉어집니다. 최근 확인 시각은 기기 간에 공유되므로 다른 접속에서 확인한 기록에는 표시가 붙습니다.

## 디자인 시스템

- **3테마**: **라이트(기본)** / 다크 / 네이비 — 사이드바 세그먼트로 전환, 선택 저장
- **표시 통화**: USD / KRW / JPY 전환 (시안 8페이지에 적용, 기존 뷰는 KRW)
- **타이포그래피**: Manrope(디스플레이) · IBM Plex Mono(숫자) · Noto Sans KR(본문)
- **우하단 시세 위젯**: JPY100/KRW · 금 1g(KRW), 전일 종가 기준
- **용어 툴팁**: YoC·과세표준·유기정기금 등 점선 밑줄 용어에 마우스오버 설명

## 실행

Vercel 호스팅 SPA입니다 — 빌드 단계 없음.

```bash
npm install                      # 서버리스 함수(Node) + 테스트 의존성
pip install -r requirements.txt  # api/dashboard.py 의존성 (yfinance, pykrx, pandas)
vercel dev                       # http://localhost:3000
npm test                         # 문법·타입·회귀 테스트 (CI와 동일)
npm run check:tax-rules          # 규칙 구조·출처 계약·사람 검토기한 확인
npm run check:tax-rules:remote   # 공식 법령·국세청 페이지까지 실제 확인
```

## 세금·증여 규칙 최신성

`tax-rules.js`가 계산값, 적용 연도, 버전, 공식 출처, 계산 가정과 제외 항목의 단일 기준입니다. 배당 관리·양도소득세·가족 증여 화면에서 접이식 근거 패널을 열어 현재 적용값과 사람 검토일을 확인할 수 있습니다. 실현손익 기록에는 당시의 `ruleSetId`도 함께 저장합니다.

`.github/workflows/tax-rule-watch.yml`이 매일 공식 법령·국세청 출처의 핵심 문구와 검토기한을 확인합니다. 변경 의심·접속 실패·검토기한 초과가 생기면 하나의 GitHub Issue를 열거나 갱신하고 워크플로를 실패시킵니다. 정상으로 돌아오면 이슈를 닫습니다. 법률 숫자는 자동으로 바꾸지 않습니다. 공식 본문을 사람이 대조한 뒤 값·가정·제외 항목·검토일을 같은 변경으로 갱신해야 합니다.

“최신”은 공식 출처 일일 감시와 최대 31일 사람 재검토를 뜻합니다. 화면은 검토기한이 지나면 `공식 근거 재검토 필요`로 바뀌며, 계산은 신고나 세무 자문을 대신하지 않습니다. 변경 이력과 갱신 절차는 `docs/tax-rule-changelog.md`에 기록합니다.

## Vercel 환경변수

| 변수 | 용도 |
|---|---|
| `KV_REST_API_URL` | Upstash Redis(KV) REST URL — 자산/가계부 등 영구 저장 |
| `KV_REST_API_TOKEN` | Upstash REST 토큰 |
| `DASHBOARD_PASSWORD` | 로그인 비밀번호 |
| `SESSION_SECRET` | HttpOnly 로그인 세션 서명 키 — 충분히 긴 무작위 값 사용 |
| `INTERNAL_API_TOKEN` | Node 서버리스 함수가 Python 내부 API를 호출할 때만 쓰는 별도 무작위 토큰 |
| `INTERNAL_API_ORIGIN` | (선택) 내부 API 호출용 고정 HTTPS origin. 미설정 시 Vercel 배포 URL 사용 |
| `GNEWS_API_KEY` | (선택) 뉴스 헤드라인 |

기존 배포와 같은 Upstash 인스턴스를 연결하면 기존 자산 데이터가 그대로 표시됩니다.
과거 `AUTH_TOKEN` bearer는 더 이상 허용하지 않으므로 배포 환경에서 제거하고, `SESSION_SECRET`과
`INTERNAL_API_TOKEN`은 서로 다른 값으로 새로 발급해 주세요.

## 구조

- `index.html` — 모든 뷰가 `<div id="view-*">`로 선언된 단일 페이지
- `tax-rules.js` — 대한민국 세금·증여 규칙 버전, 공식 출처, 계산 가정·제외 항목
- `script.js` — 데이터 엔진 + 기존 기능 뷰 (~9,100줄, 모듈 시스템 없음)
- `finance.js` — 가족 재무상태표·목표·리밸런싱·데이터 상태. `script.js`의 저장 엔진과 `cobalt.js`의 표시 헬퍼를 재사용
- `cobalt.js` — 메인 페이지 렌더러 + 라우터. `switchView`/`changeOwner`/`saveAssetsToKV`/`fetchDivData` 등을 감싸 재렌더와 데이터 신선도 기록을 통합
- `style.css` — 디자인 토큰(`:root`=라이트, `[data-theme="dark"]`, `[data-theme="navy"]`) + 시안 토큰 별칭(`--tx`, `--panel`, `--accSoft` 등)
- `api/` — Vercel 서버리스 함수 (가격/배당/환율/검색/KV 프록시/인증)
- `scripts/tests/` — 회귀 테스트. `npm test` 가 전체 게이트(문법 검사 → `tsc --noEmit` → Node 테스트 → Python 테스트)를 돌리고, GitHub Actions(`품질 검사`)가 push·PR 마다 같은 명령을 실행합니다. 개별 실행은 `node scripts/tests/<file>.mjs`

> 스크립트 로드 순서는 `tax-rules.js` → `script.js` → `finance.js` → `cobalt.js` 로 고정입니다.
> `cobalt.js`가 `CB_VIEWS`에서 `finance.js`의 렌더 함수를 참조하고, 다른 전역 함수들을 감싸기 때문에 마지막에 와야 합니다.

자세한 개발 규칙은 `CLAUDE.md`를 참고하세요.
