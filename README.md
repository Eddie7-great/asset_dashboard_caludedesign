# 가족 자산 관리

[Claude Design](https://claude.ai/design)에서 제작한 시안의 레이아웃과 테마를
그대로 구현하고, 기존 `asset_dashboard_claude-code` 앱의 실데이터(KV 자산, 시세·배당 API, 인증)를
연결한 버전입니다.

## 페이지 구성

사이드바는 **여덟 개 메뉴**입니다. 메뉴 안의 세부 화면은 제목 줄 오른쪽 링크로 옮기고, 같은 내용을 다른 묶음으로 보는 화면은 제목 줄 아래 오른쪽의 **보기 전환 줄**(밑줄형 버튼)로 바꿉니다. 예전 주소(`#view=…`)는 그대로 열립니다.

### 1. 홈
위에서부터 '확인 필요' 줄(시세 미조회·리밸런싱 범위 밖·미분류 자동이체 등 다른 화면 경고의 개수, 없으면 숨김) → 숫자 카드 5개(총액·일일손익·평가손익·연 배당·리스크, 누르면 해당 화면) → 자산 배분 평면 도넛(가운데 총액) · 섹터 집중도 타일 지도 · 평가손익 기여도 **손익 타일 지도** · 수익률 × 평가손익 점 그림 → 검색 가능한 **보유 종목 표 + 선택 종목 요약**. 보유 표는 처음 10종목만 보이고 '전체 N종목 보기'로 그 자리에서 펼칩니다.

### 2. 자산 관리
- **보유 목록** — 투자자산 등록·수정·삭제(모든 화면의 원본). 숫자 카드 4개 → 자산군 탭(주식/가상화폐/금/현금) → 검색·계좌 필터. 종목명을 누르면 **매수·매도 입력** 창, 적립식 칸을 누르면 **적립식 설정** 창이 열립니다. 보기 전환 줄:
  - **종목별** — 기본 표
  - **계좌별** — 소유주 → 증권사 → 계좌 트리, 계좌를 누르면 종목이 펼쳐짐
  - **구성원별** — 구성원 카드 필터 + 보유 자산 표 + 소유주별 자산군 구성

### 3. 투자 분석
- **성과** — 소유주별 포트폴리오 vs S&P 500 · KOSPI 정규화 차트와 기간별 수익률 표·MDD. *현재 보유 비중을 기간 시작일부터 소급 적용한 백캐스트*이며 화면에 그렇게 표기됩니다. 아래 **투자자산 추이** 카드는 매일 기록된 실제 평가액을 그립니다(부동산·부채 제외, 수익률 아님)
- **리스크** — 점수 링 + 규칙 카드 8종(집중도·가상화폐·섹터·변동성·현금·환노출·분산·레버리지) + 보조 진단 8종 + 종목 집중도 ETF 룩스루
- **구성** — 보기 전환 줄:
  - **비중 지도** — Plotly **트리맵**(전체 → 소유주 → 섹터/자산군 → 종목)으로 비중을 눌러 들어가 봅니다
  - **ETF 속 종목** — 보유 ETF의 구성종목·비중 변화, 기준일·완전성 점검, 소유주별 직접/간접 노출

### 4. 배당
세전/세후 전환, 연간·월평균·YoC·배당성장률·집중도 카드, **입력된 일반계좌 배당 기준 금융소득 부분 근접도**, 월별 배당 그래프(남은 달은 빗금 = 추정), 종목별 배당 표, 향후 90일 예상 일정.

### 5. 투자 계획
- **목표** — 목표별 진행 비교·목표 일정·목표 카드(남은 금액 ÷ 남은 개월, 수익률 0% 가정, 기한 미정 가능). 현금 안전판 **목표 개월수**도 여기서 바꿉니다
- **리밸런싱** — 목표 비중 대비 '현재 vs 목표' 막대 → 필요 조정액 → 월 적립식 보정안, 계좌 배치 진단 트리
- **적립식 매수** — 조회 전용. 켜 둔 규칙(진행 중·금액 미입력), 앞으로 10일 매수 일정, 다음 매수일, 월 환산 배분. 규칙 추가·수정·중단은 보유 목록의 적립식 칸(설정 창)에서 합니다
- **투자 시뮬레이터** — 세 개 탭. **과거 성과 백테스트**(단일 종목, 수정주가 기준 적립식), **추가 투자 배분**(새로 넣을 돈을 목표 비중대로 나누는 메모리 전용 시나리오), **은퇴 자금 예상**(오늘 돈 가치 기준 가상 계산)

### 6. 현금 흐름
머리줄 탭 세 개: **월별 현금흐름**(수입·지출 가계부, 일회성·자동이체, 수입/지출 구성 차트와 선택 달 요약) · **고정비 관리**(고정비 표·분포, 대출 상환 조건, 적립식 매수 묶음) · **일정**(적립 매수·자동이체·배당 예정일 달력). 여기서 고정비로 분류한 항목이 현금 안전판의 기준이 됩니다.

### 7. 세금·증여
- **실현손익·세금** — 월별 실현손익 기록(한 줄 입력, '보유 반영'으로 보유 수량도 줄임)·거래내역 가져오기·그래프, 해외주식 250만원 기본공제 → 지방세 포함 22%, 계좌별 구분
- **가족 증여** — 결과(합계·판정)가 위, 계획 수정은 아래 접이식. 증여 기록장과 자동이체 증여 연결

### 8. 결산 리포트
조회 전용. 보기 전환 줄로 **월간 · 연간**. 한 장씩 넘겨 보는 화면이며, 지난 달 결산은 매일 도는 배치가 남긴 기록(그날 종가 기준)을 씁니다. 기록이 없는 2026-10 이전 달은 총액만 보여 줍니다.

**데이터 상태**는 사이드바 아래쪽 상태 버튼에서 엽니다 — 항목별 출처·최근 확인 시각·상태(**정상 / 확인 필요 / 확인 전**)를 한곳에 보여 주고 카드마다 해당 소스만 다시 조회할 수 있습니다. 화면 아래에서 보유 종목·현금 흐름 등 다섯 묶음을 **CSV로 내보낼** 수 있습니다(금액 가리기 중에는 막힘).

## 디자인 시스템

- **3테마**: **기본**(밝은 본문 + 남색 사이드바) / 라이트(사이드바까지 흰색) / 다크 — 사이드바 버튼으로 전환, 선택 저장
- **표시 통화**: 자산 합계·손익은 KRW, 종목 평단가·현재가는 원래 거래 통화(원·달러·엔·호주달러)
- **차트**: 홈 기여도·섹터는 타일 지도, 비중 분석은 트리맵, 자산 배분은 평면 도넛. 손익은 이익 초록·손실 빨강·0/미상 회색
- **글꼴**: Manrope(숫자·영문) + Noto Sans KR(한글) 한 벌, 가장 작은 글자 12px
- **사이드바**: 위쪽에 환율(USD/KRW·USD/JPY·JPY100/KRW)·금 시세, 왼쪽 위 버튼으로 접기
- **금액 가리기**: 화면의 금액을 ••••로 숨김(만·억 줄임 표기 포함)
- **로그인·로딩**: 로고 막대가 자라는 등장 효과, 로그인 직후 단계별 로딩 화면
- **휴대폰(768px 이하)**: 재무 화면은 읽기 전용, 보유 목록은 카드 목록

## 실행

Vercel 호스팅 SPA입니다 — 빌드 단계 없음.

```bash
npm install                      # 서버리스 함수(Node) + 테스트 의존성
pip install -r requirements.txt  # api/dashboard.py 의존성 (yfinance, pykrx, pandas)
vercel dev                       # http://localhost:3000
npm test                         # 문법·타입·회귀 테스트 (CI와 동일)
npm run check:tax-rules          # 규칙 구조·출처 계약·사람 검토기한 확인
npm run check:tax-rules:remote   # 공식 법령·국세청 페이지까지 실제 확인
```

## 세금·증여 규칙 최신성

`tax-rules.js`가 계산값, 적용 연도, 버전, 공식 출처, 계산 가정과 제외 항목의 단일 기준입니다. 배당 관리·양도소득세·가족 증여 화면에서 접이식 근거 패널을 열어 현재 적용값과 사람 검토일을 확인할 수 있습니다. 실현손익 기록에는 당시의 `ruleSetId`도 함께 저장합니다.

`.github/workflows/tax-rule-watch.yml`이 매일 공식 법령·국세청 출처의 핵심 문구와 검토기한을 확인합니다. 변경 의심·접속 실패·검토기한 초과가 생기면 하나의 GitHub Issue를 열거나 갱신하고 워크플로를 실패시킵니다. 정상으로 돌아오면 이슈를 닫습니다. 법률 숫자는 자동으로 바꾸지 않습니다. 공식 본문을 사람이 대조한 뒤 값·가정·제외 항목·검토일을 같은 변경으로 갱신해야 합니다.

“최신”은 공식 출처 일일 감시와 최대 31일 사람 재검토를 뜻합니다. 화면은 검토기한이 지나면 `공식 근거 재검토 필요`로 바뀌며, 계산은 신고나 세무 자문을 대신하지 않습니다. 변경 이력과 갱신 절차는 `docs/tax-rule-changelog.md`에 기록합니다.

## Vercel 환경변수

| 변수 | 용도 |
|---|---|
| `KV_REST_API_URL` | Upstash Redis(KV) REST URL — 자산/가계부 등 영구 저장 |
| `KV_REST_API_TOKEN` | Upstash REST 토큰 |
| `DASHBOARD_PASSWORD` | 로그인 비밀번호 |
| `SESSION_SECRET` | HttpOnly 로그인 세션 서명 키 — 충분히 긴 무작위 값 사용 |
| `INTERNAL_API_TOKEN` | Node 서버리스 함수가 Python 내부 API를 호출할 때만 쓰는 별도 무작위 토큰 |
| `INTERNAL_API_ORIGIN` | (선택) 내부 API 호출용 고정 HTTPS origin. 미설정 시 Vercel 배포 URL 사용 |

기존 배포와 같은 Upstash 인스턴스를 연결하면 기존 자산 데이터가 그대로 표시됩니다.
과거 `AUTH_TOKEN` bearer는 더 이상 허용하지 않습니다. 무중단 업그레이드를 위해 `SESSION_SECRET`이
없는 기존 배포에서는 `AUTH_TOKEN`을 서버 내부 세션 서명 키로만 임시 사용합니다. 로그인 복구 후
`SESSION_SECRET`과 `INTERNAL_API_TOKEN`을 서로 다른 값으로 발급하고 `AUTH_TOKEN`을 제거해 주세요.

## 구조

- `index.html` — 모든 뷰가 `<div id="view-*">`로 선언된 단일 페이지
- `tax-rules.js` — 대한민국 세금·증여 규칙 버전, 공식 출처, 계산 가정·제외 항목
- `script.js` — 데이터 엔진 + 기존 기능 뷰 (~7,700줄, 모듈 시스템 없음)
- `finance.js` — 목표·리밸런싱·투자자산 추이·데이터 상태. `script.js`의 저장 엔진과 `cobalt.js`의 표시 헬퍼를 재사용
- `navigation.js` — 여덟 개 메뉴(`APP_NAV`)와 세부 링크, 보기 전환 줄(`NAV_MODES`·`NAV_HOST`), 옛 링크 해석, 메뉴 간 소유주 범위 유지
- `backtest.js` / `simulator.js` / `etf-explorer.js` — 백테스트·추가 투자 배분·은퇴 자금 예상·ETF 탐색. 모두 Cobalt 가 렌더할 때까지 함수만 정의합니다
- `workspace-pages.js` — 계좌별 보기·일정·결산 리포트 화면(조회 전용)
- `workspace-ui.css` / `etf-explorer.css` — `style.css` 뒤에 로드되어 통합 워크스페이스와 ETF 탐색 레이아웃을 덮어씁니다
- `core/*.js` + `script.js` — 예전 `script.js`(약 7,900줄)를 내용 그대로 14조각으로 이어 자른 것. 데이터·배당·자동이체·보유 목록·현금 흐름·시세·로그인·트리맵·KV·서버 연동 순이며, 이 순서대로 로드합니다
- `pages/*.js` — 화면별 렌더러(성과·구성원별·리스크·배당·증여·세금·적립식). `cobalt.js` 보다 먼저 로드하며 함수·상태 선언만 둡니다
- `cobalt.js` — 공통 헬퍼·홈 화면 + 라우터. `switchView`/`changeOwner`/`saveAssetsToKV`/`fetchDivData` 등을 감싸 재렌더와 데이터 신선도 기록을 통합
- `style.css` — 디자인 토큰(`:root`=기본, `[data-theme="light"]`, `[data-theme="dark"]`) + 시안 토큰 별칭(`--tx`, `--panel`, `--accSoft` 등)
- `api/` — Vercel 서버리스 함수 (가격/배당/환율/검색/KV 프록시/인증)
- `.github/workflows/` — 자동 배치. `품질 검사`(push·PR), `ETF 구성종목 수집`(미국 장 마감 뒤 평일 KST 07:30, 리포에 커밋), `순자산 스냅샷 기록`(매일 KST 16:40, KV에 직접 기록 — 월말 결산 보관도 함께), `세금·증여 공식 근거 점검`(매일, 알림만)
- `docs/invariants.md` — **건드리면 안 되는 것.** 실제로 사고가 났던 자리와 그 증상, `npm test` 로는 확인되지 않는 영역(워크플로·모바일 레이아웃·CDN 실패·터치)을 정리했습니다. 수정 작업을 맡기기 전에 이 문서를 먼저 읽게 하세요
- `scripts/tests/` — 회귀 테스트. `npm test` 가 전체 게이트(문법 검사 → `tsc --noEmit` → Node 테스트 → Python 테스트)를 돌리고, GitHub Actions(`품질 검사`)가 push·PR 마다 같은 명령을 실행합니다. 개별 실행은 `node scripts/tests/<file>.mjs`

> 스크립트 로드 순서는 `tax-rules.js` → `core/*.js`(13개) → `script.js` → `finance.js` → `navigation.js` → `backtest.js` → `simulator.js` → `etf-explorer.js` → `workspace-pages.js` → `pages/*.js`(화면별 렌더러) → `cobalt.js` 로 고정입니다.
> `cobalt.js`가 `CB_VIEWS`에서 다른 파일의 렌더 함수를 참조하고 전역 함수들을 감싸기 때문에 마지막에 와야 합니다. 스타일시트는 `style.css` → `workspace-ui.css` → `etf-explorer.css` 순입니다.

자세한 개발 규칙은 `CLAUDE.md`(기계가 읽는 판본)와 `docs/invariants.md`(사람이 읽는 판본)를 참고하세요.
